현재 HR 코드

이 그래프 안에서는 AI가 검색 도구를 선택하지 않습니다. 이미 받은 문서 내용을 읽고, 지정된 생성·평가 작업을 합니다.

코드가 질문 작성 AI에게
“이 자료와 평가 의견으로 질문 후보를 만들어.”
전달받는 것: 문서 내용 + 작성 지침
돌려주는 것: 질문 후보

따라서 현재 HR 코드를 ‘AI에게 도구 하나를 쥐여주는 구조’라고 표현하는 것도 정확하지 않습니다.

새 설계의 근거 조사 담당자

사용할 수 있는 도구는 개발자가 정해 줍니다. 조사 AI는 지금 어느 도구가 필요한지 선택합니다.

조사 AI가 검색 결과를 받은 뒤
“관련 페이지는 찾았어. 앞뒤 문장까지 읽어야겠어.”
지원자 문서 검색 도구관련 키워드가 있는 부분을 찾기
✓ 지금 선택: 문서 원문 읽기 도구찾은 페이지의 앞뒤 내용을 확인하기

한 개의 도구만 있어도 선택은 가능합니다. 같은 검색 도구로 무엇을 검색할지, 한 번 더 검색할지 결정할 수 있습니다. 필요 없는 도구를 늘리는 것이 목적은 아닙니다.

새 설계의 네 담당자에게 맡기는 일

총괄 에이전트

목표: 근거 있는 질문 5개와 준비 자료 완성.

고르는 일: 근거 조사에 맡기기 / 질문 설계에 맡기기 / 검토 맡기기 / 사용자에게 자료 요청 / 제출 제안.

자료가 없으면 요청하고 기다립니다. 없는 자료를 가져온 척하지 않습니다.

근거 조사 에이전트

목표: 질문에 필요한 근거와 출처 확보.

도구: 지원자 문서 검색 / 문서 원문 읽기.

선택 예: 검색어 바꾸기 → 찾은 페이지 읽기 → 근거를 확보하면 보고.

해당 지원자가 제공한 문서만 볼 수 있습니다.

질문 설계 에이전트

목표: 질문·예상 답변·꼬리 질문·평가 가이드 작성.

도구: 확보된 근거 읽기 / 질문 묶음 검사.

선택 예: 3번의 근거를 읽기 → 꼬리 질문만 수정 → 빠진 항목 검사 → 결과 반환.

검사 도구는 빠진 항목·잘못된 근거 번호·동일 문구 중복을 확인합니다. 내용의 진실성까지 보장하지 않습니다.

검토 에이전트

목표: 근거 없는 단정이나 유도 질문을 찾아 수정 의견 반환.

도구: 확보된 근거 읽기 / 질문 묶음 검사.

선택 예: 의심되는 근거를 다시 읽기 → 3번 수정 요청 또는 검토 통과 보고.

질문 수정은 설계 담당자에게 맡깁니다. 최신 질문 묶음은 제출 전에 검토해야 합니다.

문서 검색·원문 읽기는 새 설계에 추가한 기능입니다. 현재 코드에 이미 있다고 가정하지 않습니다. 단순한 질문 생성 업무라면 이런 추가 조사가 필요 없을 수도 있습니다.

State는 ‘작업을 이어가기 위해 남기는 업무 기록’입니다.

담당자가 바뀌어도 앞사람이 받은 자료와 작업 결과를 이어받아야 합니다. 무엇을 기록할지는 개발자가 정하고, 정해진 칸에 AI의 결과와 코드의 처리 결과를 담습니다.

현재 코드에 있는 기록

만들 질문 수: 5개최종적으로 몇 개를 골라야 하는지.질문 생성과 최종 선택에서 사용합니다.
읽을 자료: 채용공고·이력서·포트폴리오질문을 만들 때 참고할 내용.
사용자의 요청: 처음 생성 / 추가 / 선택한 질문 다시 작성어떤 생성 작업인지와 사용자가 남긴 수정 의견.
질문 후보와 예상 답변·꼬리 질문각 담당자가 지금까지 만든 결과.
평가 점수·문제점·수정 의견다시 작성할 때 참고할 평가 결과.
재시도 횟수와 최대 횟수코드가 더 반복해도 되는지 확인하는 기록.

새 설계는 왼쪽 기록을 활용하고, 다음을 추가

다음 담당자: 근거 조사총괄 AI가 이번에 누구에게 일을 맡겼는지.코드가 이 값을 읽고 해당 담당자를 실행합니다.
맡긴 일: 3번 질문의 개인 기여 근거 찾기전체를 다시 만들지, 일부만 보완할지 포함한 구체적인 업무.
근거의 위치: 포트폴리오 4쪽주장을 어디에서 확인했는지와 해당 원문.
방금 쓴 도구와 받은 결과예: 원문 읽기 → 팀 성과와 개인 역할의 차이 확인.각 담당자의 내부 작업 기록에 보관합니다.
질문 묶음의 버전과 검토한 버전수정된 질문을 예전 검토 결과로 제출하지 않도록 확인.
남은 호출 횟수·사용자 답변 대기코드가 반복을 제한하고, 추가 자료를 받으면 이어서 진행.

종혁님이 배운 ‘State를 읽어서 분기하는 코드’는 그대로 씁니다. 차이는 분기할 때 읽는 ‘다음 담당자’를 총괄 AI가 선택해 기록했다는 점입니다.

에이전트 노드 하나 안에서는 이렇게 반복합니다.

개발자가 계속 정하는 것담당자·도구·가능한 경로·기록할 항목·검증·반복 제한.
AI에게 맡긴 선택지금 필요한 담당자·도구·조회할 내용·추가 확인·수정 범위.

내부도 두 노드로 만들어 연결할 수 있습니다. 또는 한 노드 안의 코드로 반복할 수도 있습니다. 최대 횟수에 도달하면 코드가 멈춥니다. AI가 분기 코드나 새로운 도구를 즉석에서 만드는 것은 아닙니다.

현재는 “다음에 갈 곳”을 코드가 정합니다.
새 설계는 “갈 수 있는 곳”을 코드로 만들고,
AI가 그중 필요한 곳을 선택합니다.

새 설계도 마지막 검토와 실행 제한은 코드가 강제합니다. 상황에 따른 선택이 필요 없는 업무라면, 현재의 정해진 흐름이 더 단순하고 적합할 수 있습니다.

비교의 근거와 범위
  • 현재 흐름은 실제 그래프 구성, 생성·평가·재시도 처리, 업무 기록 정의를 확인했습니다.
  • 현재 자동 재시도는 리뷰 의견을 받아 보완 후보를 추가합니다. 기존 후보를 모두 버리지 않으며, 답변·꼬리 질문도 보완할 대상이 있을 때만 생성합니다. 재시도 상한에 도달하면 품질 미달이어도 종료될 수 있습니다.
  • 새 설계의 역할별 선택·추가 도구·자료 확인 대기는 설명용 제안입니다. 실제 구현·비용·성능 검증 결과는 아닙니다.
